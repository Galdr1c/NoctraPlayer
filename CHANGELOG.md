# Changelog

All notable changes to Noctra Media Player are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`THIRD-PARTY-NOTICES.md` — distribution license audit**: a repository-level notice covering every third-party component shipped in public builds (desktop + Android) with version, license and obligation notes. Key findings pinned in writing: the vendored `libffmpegJNI.so` is **LGPL-2.1-or-later** (verified from the build's own `config.h`: native decoders only via `--disable-everything`, no GPL/nonfree components), which requires offering relinkable artifacts/source for the statically-linked FFmpeg part — the published `tools/android/build-ffmpeg-16k.sh` plus unmodified upstream sources satisfy the build-recipe half, with an explicit pre-release TODO to publish the object files or a written-offer contact (LGPL §4/§6); desktop libVLC is dynamically linked (LGPL-safe); LibVLCSharp is LGPL-2.1-or-later; Avalonia/Microsoft/CommunityToolkit stacks are MIT; Google SDKs Apache-2.0-based terms; HMS kits under Huawei SDK terms. Must be re-verified against `<PackageReference>` sets on every dependency change.
- **16-KB-page-size FFmpeg build pipeline (`tools/android/build-ffmpeg-16k.sh`)**: a self-contained, re-runnable script that reproduces the vendored FFmpeg audio extension binaries from source — clones media3 `decoder_ffmpeg` @1.4.1 (the exact version of the packaged `ffmpeg-extension.jar`, keeping the JNI surface in sync), downloads FFmpeg n6.0.1, builds static libs for arm64-v8a and x86_64 with the upstream media3 configure flags (same 16-decoder set as `FfmpegLibrary.getCodecName` advertises: aac, mp3, ac3, eac3, truehd, dca, vorbis, opus, amrnb, amrwb, flac, alac, pcm_mulaw, pcm_alaw, h264, hevc), links `libffmpegJNI.so` with `-Wl,-z,max-page-size=16384` **and `-static-libstdc++`**, strips it, verifies LOAD segment alignment via `llvm-readelf`, and prints copy commands for the vendored `Noctra.Android/libs/ffmpeg/<abi>/` paths.

- **Mobile-specific Privacy Policy and Terms of Use (Android)**: the Android app previously reused the desktop legal texts (Microsoft Store purchases, Windows DPAPI, `Documents\Noctra` paths), which did not describe Android reality. New `GlobalSettings.Privacy.Message.Mobile` / `GlobalSettings.Terms.Message.Mobile` localization keys (all five languages: en, tr, de, fr, es) are shown by `MobileSettingsView` and the first-launch `MobileLegalConsentView`; desktop call sites keep the unchanged `*.Message.Current` texts. The mobile texts declare what Android users need to know: Google AdMob via the Google Mobile Ads SDK and Huawei Petal Ads (HMS Ads Kit) in the free version with per-SDK data practices per Google's disclosure, the UMP / HMS consent flows gated behind Noctra's own first-launch legal consent, Android Keystore-backed AES-GCM credential protection, local-only profiles / watch history / downloads, TMDB metadata requests (searched titles + language, adult content excluded), and Google Play billing verified through the stateless Kynora Studio backend (purchase token + product ID + package name only, no card data, no stored installation identity). The provider-connections section explicitly discloses cleartext `http://` traffic (required for many IPTV sources; matches `network_security_config.xml`) so Play review and the Data Safety form have an in-product answer. Matching mobile pages (`privacy-mobile.html`, `terms-mobile.html`) were added to the Kynora Studio site with identical wording (site repo: `D:\KynoraStudio\Noctra`). Source-contract tests pin per-language revision dates, required headings, and mandatory disclosures for both document sets.

### Changed

- **Child-profile sections removed from all legal documents; revision date moved to August 25, 2026**: the dedicated "Children and Profiles" / "Profiles, PINs, and Child Features" sections (and the "child-profile settings" item in the stored-data lists) are removed from Privacy and Terms in every surface — desktop (`*.Message.Current`), Android (`*.Message.Mobile`), all five languages, and all four website pages (renumbered headings + TOC). The child-profile feature itself is unchanged; only the legal text no longer calls it out. Tests now assert the sections are absent (`DoesNotContain`) in all languages and pin the new revision date in both desktop and mobile documents.

- **Persistent banner ad at the bottom of the content area**: a new `MobileBannerAdControl` is pinned to the bottom of `MainView`'s content column (`Grid.Row="1" Grid.Column="1"`, `RowDefinitions="*,Auto"`) and is visible on every shell page — Home, Live, Movies, Series, Search, Downloads, More — for free users only. In portrait it sits directly above the bottom navigation bar; in landscape/tablet mode (width ≥ 720, navigation rail active) it stays at the bottom of the content area to the right of the rail. It collapses to zero height when the user is Premium, when consent/SDK is not ready, or when the provider serves no ad; `IsSuppressed` hides a loaded ad (keeping it alive) while the player or an overlay is open. `IMobileAdvertisingService.CreateBannerAd(host)` is the provider boundary; the Android `AdMobMobileAdvertisingService` embeds a fluid Google `AdView` via `NativeControlHost` and returns a disposable handle that destroys the view on release.

### Changed

- **Minimum Android version reviewed and deliberately kept at 9 (API 28)**: A review flagged that `SupportedOSPlatformVersion=28` conflicts with README's "Android 12+" claim. History: the project was created at 31 (June 2026) and silently lowered to 28 in July alongside unrelated UI work. The decision now is to keep 28 as an intentional choice — documented with a csproj comment so it is no longer accidental — which means Play will offer the app on Android 9–11 and those surfaces need real-device testing before store text claims any support level; the README "Android 12+" text still needs alignment (either update it to Android 9+ or raise minSdk back to 31 later).
- **Desktop and mobile versions explicitly decoupled in the build**: a review flagged that root `Directory.Build.props` defines `NoctraVersionPrefix=1.2.0` while `Noctra.Android.csproj` pins `ApplicationDisplayVersion=1.0.0` — functionally correct today (only `Noctra.Avalonia` consumes the prefix, and Android reads the real manifest values at runtime through `PackageManager`/`AndroidAppVersionService`) but only accidentally so, since nothing prevented a future edit from wiring the desktop prefix into the mobile properties. The split is now documented as deliberate in both files: `Directory.Build.props` carries a DESKTOP-ONLY warning pointing at the Android csproj, and the Android `ApplicationVersion`/`ApplicationDisplayVersion` block states that mobile ships its own versionName/versionCode and must never be replaced by `$(NoctraVersionPrefix)`/`$(NoctraPackageVersion)`.
- **Native feed ads removed**: the in-feed native ad system is gone. Deleted `MobileNativeAdHost`, `MobileNativeAdSurfaceCoordinator`/`MobileNativeAdOverlayGuard`, `AdPlacementPlanner`, `AdAwareIncrementalRowCollection` (renamed to `IncrementalRowCollection`, now a plain row projection), the `AdPlacement` property on the virtualizing grids/feeds, and all `AdPlacement=...`/`NativeAdInsertAfterSection=...`/`MobileNativeAdOverlayGuard.IsEnabled=...` XAML bindings. `IMobileAdvertisingService` no longer exposes `PrimeNative`/`TryCreateNativeAdControl`/`ReleaseOwner`; `AdvertisingOptions` keeps only `PlaybackExit` (interstitial policy). The Android csproj's native ad unit IDs (`NativeLive/Movies/Series/Search`) and their `AssemblyMetadata` entries were removed; banner + interstitial unit IDs remain.

- **Remote ad configuration removed**: `RemoteAdvertisingConfigService`, `IRemoteAdvertisingConfigService`, and `RemoteAdvertisingLimits` are gone. Advertising policy is now entirely in-app (`AdvertisingOptions.ConservativeDefault`); the `NOCTRA_ADVERTISING_CONFIG_URL` build-time metadata, the `LoadAdvertisingConfigFromDotEnv` msbuild target, and the `.env` entry were deleted. `MobileAdvertisingBootstrapper` no longer fetches remote config (entitlement → consent/init only), and `AdMobMobileAdvertisingService`/`PreviewMobileAdvertisingService` no longer subscribe to `OptionsChanged`.

### Removed

- **Background playback removed — Picture-in-Picture is now the single off-screen playback path**: The mobile Settings toggle ("Arka Plan Oynatma" / "Background Playback") and the entire policy behind it are gone. Previously, enabling `AppSettings.AllowBackgroundPlayback` kept ExoPlayer streaming while the app was backgrounded (foreground media service + wake-lock + background network buffering). That produced a class of hard-to-reproduce bugs: live streams stalled silently in the background, returning to the app showed endless buffering, and tapping Play appeared dead because ExoPlayer's `PlayWhenReady` was already true while the renderer was stuck — there was no deterministic recovery path. The replacement policy is simple and testable: **playback never moves to the background unless Picture-in-Picture took over**. Free users get HOME → `MainActivity.OnStop()` → `Pause()`; premium PiP users keep playing under Android's control (`IsInPictureInPictureMode` short-circuits the pause); coming back to the foreground resumes automatically because the `_pausedByLifecycle` flag distinguishes lifecycle pauses from the user's own manual pause. Removed end-to-end: the `AllowBackgroundPlayback` property (model, profile/global settings sync, ViewModel auto-save list, load-from-settings, form snapshot record + apply), the toggle row in `MobileSettingsView.axaml`, the `Settings.Playback.BackgroundPlayback` key in all five languages, the settings branch in `MainActivity.OnStop()` (now one unconditional pause outside PiP), and `NoctraPlaybackService`'s `ISettingsService` dependency — `OnTaskRemoved` now always calls `PauseAllPlayersAndStopSelf()` instead of honoring a keep-playing exception. Deliberately **kept**: `NoctraPlaybackService` itself, its MediaSession/notification plumbing, the manifest permissions (`FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `WAKE_LOCK`, `FOREGROUND_SERVICE`) and the premium-gated automatic PiP — the service/MediaSession chain is what PiP and the media notification ride on, and tearing it out would have been a much larger redesign for no benefit. Old `settings.json` files still containing the field need no migration (System.Text.Json ignores unknown properties on load). README/CONTRIBUTING feature lists updated; the release-guard contract test now asserts the service has *no* background-playback branch. Known deferred follow-up: for live channels a long background stay may deserve a live-edge re-prepare on return instead of plain `Resume()` (VOD/series resume-with-position stays correct as-is).

### Fixed

- **FFmpeg audio extension rebuilt with 16-KB ELF page alignment; XA0141 suppression dropped**: The vendored `libs/ffmpeg/{arm64-v8a,x86_64}/libffmpegJNI.so` binaries were built with 4-KB LOAD segment alignment (`p_align=0x1000`, NDK r26b). Google requires 16-KB alignment for updates published after Feb 2027, so every future update would have been blocked at Play upload. Both binaries were rebuilt from source (media3 `decoder_ffmpeg` @1.4.1 + FFmpeg n6.0.1, same decoder set, verified identical Lavc60.3.100 and decoder long-name strings against the old artifacts via embedded strings) with `-Wl,-z,max-page-size=16384`; all LOAD segments now report `p_align=0x4000`. Two build pitfalls were caught and fixed along the way: **(1)** on Windows/Git-Bash the FFmpeg root's extension-less `version` file collides with libc++'s `<version>` header on the case-insensitive filesystem while compiling `ffmpeg_jni.cc` (moved aside for the JNI step); **(2)** linking `clang++` without `-static-libstdc++` added a `libc++_shared.so` DT_NEEDED entry the app does not package — `dlopen` failed silently, `FfmpegAudioRenderer` never loaded (`DefaultRenderersFactory` skips unavailable extensions), and EAC3 audio streams fell back to MediaCodec and died with `ExoPlaybackException ... format_supported=NO_UNSUPPORTED_TYPE`, i.e. videos stopped opening. Relinking with `-static-libstdc++` restored a NEEDED list identical to the old binary (`liblog/libm/libdl/libc`). Verified end-to-end on the Huawei DBY-W09 device: Release build passes **without** the previously suppressed XA0141 diagnostic (removed from `NoWarn`; the csproj comment now forbids re-adding it — fix the binary instead), the AAB packages only the arm64 artifact (3.6 MB stripped vs 6.4 MB debug-info-laden predecessor), logcat shows `Loaded FfmpegAudioRenderer.` and continuous playback with zero playback errors. Reproducible via the new `tools/android/build-ffmpeg-16k.sh`.
- **Adult-last ordering no longer degrades deep scroll in Live/Movies "All" (offset pagination replaced with two-phase keyset)****: Symptom: after the adult-categories-last feature, browsing "Tümü/All" on playlists that contain adult groups silently lost keyset pagination — every page for Newest/Oldest order ran `ORDER BY isAdultFlag, Id DESC` + `SKIP n TAKE 30`, so per-page cost grew linearly with scroll depth on large providers. Root cause: the adult-last composite sort needs two sort keys while `ContentPageCursor` carried only `LastId`, so the service disabled keyset whenever adult groups existed (`!hasAdultGroupOrdering` gate). Fix: `ContentPageCursor` gained an `AdultPhase` flag and `PlaylistService.GetTwoPhaseKeysetPageAsync` now serves the logical sequence [normal segment | adult segment] as two indexed keyset queries — normals continue past the cursor until exhausted, the boundary page is filled from the start of the adult segment, and a phase-flagged cursor continues inside the adult segment only; deep-scroll cost is constant per page again. Group matching uses SQL-side `TRIM()` because caller-supplied names come from the group-metadata cache (trimmed originals) while stored `GroupTitle` values can carry padding. The ViewModel now tracks `_lastChannelCursorAdultPhase` (derived from whether the page's last row belongs to a known adult group) and passes it into the cursor. Additionally, a caller-supplied `AdultGroupsLast` set is now authoritative: `PlaylistService` no longer re-queries playlist state + distinct group titles from the DB on every page when the ViewModel already knows the set (null still falls back to DB discovery for the transitional window before metadata loads). Deliberately NOT changed: A-Z/Z-A sorts keep offset pagination (they never had keyset), search and selected-category flows keep their existing ordering, and no schema migration/backfill was added (a persisted `IsAdultCategory` column remains a future option if profiling ever demands it). Follow-up hardening after self-review caught two edge cases: **(1) empty authoritative set duplicated pages** — an explicitly empty `AdultGroupsLast` array with a cursor entered the two-phase helper, whose empty-set branch dropped the keyset predicate entirely, so on playlists without adult categories page 2 re-served page 1 (the entry gate now requires a non-empty caller set so empty sets take the plain keyset path, and the helper applies the keyset predicate unconditionally); **(2) padded raw group titles broke `AdultPhase` derivation** — the ViewModel compared raw `GroupTitle` values against trimmed metadata names with exact `Contains`, so a boundary page ending on `" FOR ADULTS "` kept `AdultPhase=false` and the next page re-served normal rows (the new `MainViewModel.ComputeAdultSegmentCursorPhase` trims both sides and is deliberately case-sensitive to mirror the binary SQL `IN` — a case-insensitive phase would skip rows on the service side). Moving phase derivation entirely into the service via a `NextCursor`-carrying result type remains a deferred architectural follow-up. Verified by new integration tests: two-phase boundary crossing across pages for Newest/Oldest with spaced raw group titles, empty-authoritative-set paging over 65 items with zero duplicates (both directions), caller-authority override test proving DB rediscovery is skipped, `ComputeAdultSegmentCursorPhase` unit tests, plus contract tests pinning the plumbing; full suite 2337 tests green.
- **One-frame "Filtreleme hatası" flash when switching profiles**: Symptom: right after tapping a profile, a filter-error status message appeared for a moment and then vanished once real content finished loading. Root cause: profile reset raced its own filter pipeline — `ClearProfileState()` reset observable properties whose change handlers scheduled filter requests against the just-cleared state, `OnSelectedSortOrderChanged` ignored both suppression flags (unlike the group handler), and the filter pipeline's `catch` surfaced any exception from these doomed startup requests directly as `Main.Status.FilterError`. Fix: `ClearProfileState()` now cancels pending filter requests first and wraps all selection resets in temporary `_suppressFilterRefresh`/`_suppressNavigationFilterRefresh` (restored via try/finally; cleanup owned by the `SelectedPlaylist=null` transition still runs because it is gated by `_suppressSelectedPlaylistChanged`); the sort-order handler respects the same suppression flags; and the pipeline's catch block returns silently when the failed request was already superseded or cancelled (`request.Token` / `_activeFilterRequest` identity check) instead of writing a user-visible error for state nobody asked about. Contract tests pin the suppression in the sort handler, the atomic reset wrapper, and the stale-request guard.
- **Banner ads no longer turn blank and unclickable after long background or screen-off periods**: After roughly 20–30 minutes away (HOME, another app, or the screen simply off) the persistent bottom banner could reappear as an empty solid-color strip occupying its slot but rendering no creative and ignoring taps. Root cause: Android suspends the ad view's internal renderer/WebView while the host activity is stopped, and when the creative dies this way neither Google's nor Huawei's banner raises any failure callback — so `MobileBannerAdControl` kept treating the non-null handle as a loaded ad (`LoadAd()` early-returns on `_adisposable != null`) and nothing ever healed the stale shell. Fixed in two layers. **Layer 1 — the AdMob native host now follows Google's recommended `AdView` lifecycle**, closing its parity gap with HMS: `MobileAppLifecycle.Paused` → `adView.Pause()`, `MobileAppLifecycle.Resumed` → `adView.Resume()`, plus a resume-time heal that rebuilds the AdView inside its live container whenever it comes back detached from the window (a state a suspended renderer can produce, and one a dead creative can never report by itself); lifecycle subscriptions are released exactly when the native view is destroyed. **Layer 2 — a provider-agnostic stale safety net in `MobileBannerAdControl`**: the control records when the app left the foreground and, once the absence exceeds a threshold (**2 minutes in release / 15 seconds in Debug** so the path is verifiable on a device without a half-hour wait), destroys the current ad and issues a completely fresh request via `ClearAd()` + `LoadAd()` — deliberately bypassing the loaded-handle early-return, which was the bug's escape hatch. While suppressed (player/overlay open) the recreate stays dormant until chrome returns, so no impression is requested for a hidden view. Verified on a real device (HMS provider): both the HOME and screen-off scenarios log `banner stale after Ns in background -> recreate` and show a fresh `loaded` + impression within ~0.5 s. New source-contract tests pin both layers (lifecycle pause/resume + detached recreate in the AdMob host; threshold + destroy/reload order in the control).
- **Resume-recovery final layout attempt no longer mutates the grid from a background thread**: code-review follow-up on the grid recovery work — `RecoverAfterResumeAsync` awaits with `ConfigureAwait(false)`, so after the first attempt the continuation (including the 2-second-deadline timeout path) runs on the thread pool, and the timeout path called `ArmLayoutUpdatedRetry` directly, subscribing to the Avalonia control's `LayoutUpdated` event from a worker thread (racy event mutation, racing `DisarmLayoutUpdatedRetry` on detach). The arm is now posted through `Dispatcher.UIThread.Post` at `Loaded` priority with a fresh `IsResumeRecoveryEligibleOnUiThread(version)` re-check (stale generation / detached grid skip arming entirely), and `ArmLayoutUpdatedRetry` asserts UI-thread access. Source-contract test pins the post-before-arm ordering and the UI-thread assert.
- **One throwing lifecycle handler can no longer silence the others**: `MobileAppLifecycle.Resumed`/`Paused` invoked the multicast delegate directly, so a single subscriber exception (any grid, the banner control, or an ad host) prevented every later subscriber from receiving the resume/pause signal — a "app came back but parts never recovered" failure class. `TryNotifyResumed`/`NotifyPaused` now iterate `GetInvocationList()` with per-handler try/catch and log failures (`[Noctra] Lifecycle handler failed: ...`) so isolation is observable in adb logcat. Behavior test proves a throwing handler no longer blocks earlier or later subscribers.
- **`OnStop` now pauses Opening/Buffering playback too (zero tolerance outside PiP)**: the background-playback removal left one hole — a player in `Opening`/`Buffering` state (`IsPlaying == false`) when HOME was pressed escaped the pause, and once the buffer filled in the background, playback could start by itself, violating the "playback never moves to the background unless PiP took over" policy. `MainActivity.OnStop` now pauses when `IsPlaying` **or** state is `Opening`/`Buffering`. To protect the user's manual pause from the paused-seek edge (seek while paused briefly reports `Buffering`), the auto-resume flag is now `_pausedByLifecycle = player.IsPlaying` — only a player that was genuinely playing earns an automatic `Resume()` on return; a paused-seek buffering window stays paused. Contract test pins both the state list and the flag semantics.
- **`OnTrimMemory` no longer clears the image cache on informational levels**: every trim level — including `UiHidden`, which fires every time the app merely leaves the foreground — called `RemoteImage.TrimImageCaches()`, so returning from even a seconds-long background re-decoded every visible poster and produced return jank on low-end devices. The cache now clears only on real pressure levels (`RunningLow`, `RunningCritical`, `Moderate`, `Background`, `Complete`); `UiHidden`/`RunningModerate` keep the warm cache because the user may return at any moment. Contract test pins that `UiHidden` is excluded from the trim path.
- **Detached card controls no longer stay pinned by their ViewModel collections**: `MobileVirtualizingCardGrid` kept its `SourceItems` `CollectionChanged` subscription and `MobileSectionedCardFeed` kept its per-section `PropertyChanged` + source `CollectionChanged` subscriptions after being detached from the visual tree — since the delegate target is the control, a long-lived ViewModel collection (Search results, favorites, history) kept every detached feed/grid and its realized rows alive. Both controls now release those subscriptions on detach and reclaim them on re-attach, and re-attach performs a full rebuild from the current source state (detached changes were intentionally not observed, so nothing can be missed). The grid's `OnSourceItemsChanged` also only subscribes while attached. Contract tests pin the release/reclaim calls on both controls.
- **Live/Movies/Series card grids no longer depend on a ~100 ms window to survive a resume**: On the Live TV screen (most noticed there; Movies/Series/Home use the same control) cards could stay unloaded after the app returned from a long background stay or screen-off — the user had to switch to another screen and back to get content. Two confirmed code weaknesses matched the symptom class, both now fixed. **(1) Grid resume recovery gave up too early**: `MobileVirtualizingCardGrid`'s post-resume layout repair ran exactly 3 attempts 50 ms apart (~100 ms total) and, if `VisualRoot` was still null or `Bounds.Width < 120` by then, logged a timeout and stopped — `_fullRebuildRequired` stayed set but nothing re-queued it until an actual size change or navigation, leaving a blank/mis-measured grid. The stale comment even claimed a "350 ms timeout". The recovery is now deadline-bounded instead: the original three fast attempts always run, polling continues up to **2 seconds**, and on timeout a final **event-driven attempt is armed on `LayoutUpdated`** so the next real layout pass heals the grid even if the surface took longer than the deadline; the armed attempt is disarmed on detach/pause via the generation guard. **(2) Page image activation had the same ~100 ms patience**: pausing clears every `RemoteImage` source on the active page, and the resume path re-activates loads through `TryActivatePageImagesIfCurrent`, which could permanently miss if the content host was not yet effectively visible — with the page's `SurfaceLoadsActive` flag false, `IsLoadEligible` blocks **every** image on the page, including rows realized later by scrolling. `MainView` now schedules one delayed verification (2 s after resume) that re-activates loads only when the flag is still false — the flag read makes it a no-op (no image reload churn) whenever the normal path succeeded. Deliberately NOT changed: `MobileSectionedCardFeed` (it rebuilds unconditionally with a fallback width, so it cannot end up un-rebuilt), the page scroll-restore retry count, and the banner/interstitial flows. Reproduction note: five automated on-device attempts (2 min HOME, 5 min screen-off, 25 min screen-off, 25 min HOME + screen-off, and restricted standby bucket + battery simulation) all came back clean on the Huawei DBY-W09 — EMUI never froze the process (`isFrozen=false`), so the exact real-world trigger (likely EMUI power management on battery, memory pressure, or process freeze) was not reproduced in the lab. Because of that, both new failure paths log to adb logcat (`Grid resume recovery timed out ... arming a final layout-driven attempt`, `Grid resume final layout attempt running`, `Late image activation healing page after resume`) so the next real occurrence identifies itself. Contract tests pin the deadline, the layout-driven final attempt, and the eligibility-gated image heal. Regression verified on device with the fixed build: cold start, Live navigation, and HOME + 3 min screen-off resume all render correctly with no timeout logs.

## [1.2.0] - 2026-08-11

### Added

- **Event-driven review prompt system**: The in-app review prompt is now triggered by meaningful user experiences in addition to the existing launch-count gate. A new `ReviewPromptTracker` mediates between experience-recording sites and the prompt services via an internal `PromptRequested` event, keeping the eligibility logic in a single shared `ReviewPromptPolicy` class (Android and desktop no longer duplicate `IsEligible`, `MinimumLaunches`, `SnoozeDuration`, or `PromptDelay`). Three new conditions must **all** be satisfied before a prompt fires: (1) at least **1 provider added** (profile or playlist successfully saved), (2) at least **3 meaningful playback sessions** (≥ 30 s of real content), and (3) at least **30 minutes of cumulative real watch time** — all tracked in `AppSettings` as `ReviewPromptProviderAddCount`, `ReviewPromptPlaybackCount`, and `ReviewPromptTotalPlaybackSeconds`. Watch time is accumulated in `PlayerViewModel` from the same delta fed to the watch-history timer and includes the final tail segment that would otherwise fall between ticks. A new `IReviewPromptService.TryShowPromptAsync()` entry point handles event-driven calls without bumping the launch counter or waiting for the long startup settle delay (10-second UI-owner timeout instead of 30 minutes); Android uses it directly while the desktop service subscribes to the tracker's event. `SettingsService` copies, resets, and excludes all three new fields consistently with the other review-prompt persisted state. Tests updated to cover serialization include and exclusion of the new fields.lds.

- **Shared mobile player touch/remote input mode**: Android player, EPG, timeline, and player sheets now share the last active input mode for consistent touch, D-pad, and Bluetooth-keyboard behavior. The first navigation key reveals hidden controls and focuses Play/Pause, VOD/series timelines support 10-second left/right seeking, player actions have visible keyboard focus without Fluent's white default adorner (including when focus returns to the player root), sheets focus the selected/first action and restore their opener, and Back closes nested panels before hiding the overlay or exiting playback.

- **EPG focus behavior coverage**: Added runtime behavior tests for preserving the time anchor during vertical guide navigation, recovering the selected program after virtualized rows are rebuilt, and retaining selection across touch/remote scale transitions. Existing source-contract tests remain architecture guards rather than substitutes for these behavior checks.

- **Mobile upsell purchase flow feedback**: the mobile Premium sheet now disables the purchase buttons and shows a spinner while a purchase is in flight, evaluates the `StorePurchaseResult` (success and user-cancel close the sheet; already-owned shows an info message; technical failures keep the sheet open with a localized error and the option to retry), and no longer closes the sheet unconditionally in `finally`. Product pricing failures now show `—` prices with a localized retry action.
- **Subscription offer selected explicitly (not first offer)**: the Android store service reads `offerId`, offer tags, and all pricing phases via JNI (including `recurrenceMode`) and prefers the trial/intro-free base-plan offer — the displayed price always comes from the recurring phase, and the same offer's token is used for the purchase flow, so a trial or introductory price can no longer be shown as the monthly price or sent to the purchase flow.
- **Cached store entitlement applied at cold start**: `LicenseService` now synchronously loads the last server-verified store entitlement (lifetime / subscription) from the persisted cache in its constructor, before the async Play refresh completes. This removes the brief Free→Premium UI jump on launch and prevents a paid user from appearing Free during a slow/offline refresh — the cached value respects the real Play `expiryTime`, so an expired subscription still resolves to Free. A successful refresh overwrites the cache as before.
- **Acknowledge result now evaluated**: `AcknowledgeIfNeeded` in the Android store service checks the `BillingResult.ResponseCode` returned by `AcknowledgePurchaseAsync` instead of discarding it — non-OK responses (e.g. `SERVICE_UNAVAILABLE`, `NETWORK_ERROR`) no longer pass silently. Transient failures are logged distinctly from permanent ones; both are retried automatically on the next query because the purchase remains locally unacknowledged. Entitlement is unaffected by acknowledge state (it is granted by backend verification; acknowledge only prevents Play's 3-day auto-refund).
- **Lifetime purchases acknowledged on every restore**: `GetEntitlementAsync()` now acknowledges every `PURCHASED` record — including the one-time lifetime package — before entitlement verification, independent of the verification client. Google Play auto-refunds unacknowledged non-consumables after 3 days, so this covers missed purchase callbacks (interrupted flow, app kill, purchase on another device, restore).
- **Resume/focus re-validates Play entitlements**: `RefreshSubscriptionStatusAsync()` now performs a real store (Google Play) query instead of only syncing local settings — purchases completed on another device, refunds, cancellations, account holds, or grace-period changes that happened while the app was backgrounded are picked up on Android `OnResume` and desktop `Activated`. Concurrent refreshes (startup, `EntitlementChanged`, resume) are serialized with a lock; a failed query never downgrades the last verified entitlement, and `SubscriptionChanged` notifications are marshalled to the UI thread via the dispatcher (same pattern as the expiry timer).
- **Automatic Premium expiry refresh**: While the app stays open, a timer fires at the exact moment a timed Premium (subscription or promo) expires and pushes a `SubscriptionChanged` notification so the Premium badge, buttons, and feature gates refresh immediately. As a backup, the expiry is re-checked whenever the app regains focus/resumes on both desktop (`Window.Activated`) and Android (`OnResume`). Long durations (over 24 h) are re-armed periodically so system clock changes and long sleeps are also caught.
- **Play Billing IAP on Android**: Premium can now be purchased directly from Google Play — a monthly auto-renewing subscription and a one-time lifetime package. The upsell sheet shows both plans with live store prices; entitlement is re-verified from Play on every launch and whenever purchases change. Lifetime always wins; otherwise the later of subscription/promo expiry applies. Product IDs (`noctra_premium_monthly`, `noctra_premium_lifetime`) must be created in Play Console.
- **One-command backend deploy**: `deploy-billing.sh` / `deploy-billing.ps1` deploy `Noctra.Billing.Api` to Google Cloud Run in the free-tier region (`us-central1`), upload the service-account JSON to Secret Manager, and write the resulting `NOCTRA_BILLING_VERIFY_URL` into `.env` for the next Release build. `smoke-test-billing.sh` validates the deployed endpoints. Browser-only one-time steps are documented in `docs/play-console-setup-checklist.md`.
- **Premium source is now tracked**: `SubscriptionInfo` carries a `PremiumSource` (`GooglePlayLifetime`, `GooglePlaySubscription`, `Promo`, `PremiumEdition`) so UI can tell how Premium was obtained. `LicenseService` exposes `HasLifetimePremium`, `HasActiveStoreSubscription` (a monthly subscription still renewing on Google Play, independent of a lifetime package), and `CurrentPremiumSource`.
- **Real trial detection end-to-end**: the billing backend reads the user's current phase directly from `subscriptionsv2.get` → `lineItems[].offerPhase` — the **presence of `offerPhase.freeTrial`** means the user is in a free trial (no extra Monetization API call needed; `introductoryPrice` and `basePrice` are separate phase types). The `IsTrialPeriod` flag is carried through the backend response to the client (`BillingVerifiedEntitlement` → `StoreEntitlement`) and into `LicenseService`, which marks `SubscriptionInfo.IsTrialPeriod` only for a real trial — a paying monthly user can never appear as a trial, and a paid introductory offer is not treated as a trial either. Trial detection is best-effort (offerPhase absent → false, entitlement is never blocked). The backend is stateless, so no schema or store is involved.
- **Play Developer API schemas now parsed exactly as Google defines them**: a review against the real API reference exposed several inverted/incorrect field readings that tests had encoded the same way. (1) **Lifetime `purchaseState` was inverted** — `purchases.products.get` uses `0=Purchased, 1=Canceled, 2=Pending` (not the BillingClient client-side enum), so real lifetime purchases were rejected and canceled/refunded ones granted Premium; now `0` grants and state maps to `PRODUCT_PURCHASED/CANCELED/PENDING/UNKNOWN`. (2) **`autoRenewing` was read from the subscription root where it does not exist** — it lives at `lineItems[].autoRenewingPlan.autoRenewEnabled`, so it was always `false`; now read from the matching line item. (3) **`expiryTime` was taken from any line item** (max across all, even mismatched products); now a non-matching line item `continue`s and cannot contribute to the requested entitlement. (4) **`PAUSED` and `ON_HOLD` no longer grant Premium** (Google revokes access in both); `ACCOUNT_HOLD` is not a current enum value — the name is `ON_HOLD`, and unknown states stay fail-closed. (5) **Trial detection rewritten to a single request**: Google reports the current phase directly via `lineItems[].offerPhase` — the presence of `offerPhase.freeTrial` means the user is in a free trial, so the separate Monetization API call (whose schema was also misinterpreted) was removed entirely. Test fixtures were rewritten to model the real Google JSON shapes, including new paused/on-hold/pending-lifetime/paid-intro scenarios.
- **Diagnostic reports are now current and accurate**: bug/crash reports no longer show a bare `Status: Free/Premium`. A shared `DiagnosticLicenseReport` builds the live license state — `Premium Source` (lifetime / subscription / promo / edition), `Premium Expires (UTC)`, `Trial: Yes` (only real backend-verified trials) and `Pending Purchase: Yes` — identically on Android and desktop. The desktop report now resolves the app version through `IAppVersionService` (entry-assembly version) instead of the Core assembly version, both platforms include `App Build` (Android versionCode), `Locale`, and a `Report Generated (UTC)` timestamp.
- **Billing backend is now fully stateless**: Noctra has no central user account and the entitlement's source of truth is Google itself, so the persistent entitlement database and RTDN were removed entirely — the backend is a single `POST /billing/google/verify` that asks Play for the real state and returns it. Deleted: `EntitlementStore` (SQLite + `Microsoft.Data.Sqlite`), the `GET /billing/entitlement` endpoint, the RTDN push endpoint (`/billing/google/rtdn`), `OidcTokenVerifier`, the subscription/one-time/voided RTDN notification models, the token→installation mapping, and the multi-device DB update logic. The Android client is unaffected (it never used `/billing/entitlement`): on every launch/resume/purchase it sends the token and gets the current Play state, so no capability is lost — cancellations/refunds simply reflect when the user next opens the app.
- **Google Play API auth now uses ADC (Application Default Credentials)**: instead of a service-account JSON in Secret Manager plus a manual RS256 JWT assertion, the backend resolves `GoogleCredential.GetApplicationDefault()` scoped to `androidpublisher` — on Cloud Run the attached service identity (`noctra-billing-runtime@…`) supplies the token automatically from the metadata server. No private key to store, rotate, or leak; local development uses `gcloud auth application-default login`. Both deploy scripts create the service account, attach it to the Cloud Run service, and drop the Secret Manager + `NOCTRA_GOOGLE_CREDENTIALS_JSON`/`NOCTRA_RTDN_*` plumbing (docs/play-billing-verification.md rewritten accordingly).
- **Billing request no longer carries an installation ID**: `BillingVerifyRequest` was slimmed to `purchaseToken` + `productId` + `packageName` (backend is stateless and never used the value). Removed end-to-end: `AppSettings.InstallationId`, `EnsureInstallationIdAsync` in the Android store service (and its now-unused `ISettingsService` dependency), the settings copy/reset lines, and the smoke-test fields.
- **Billing config fails fast on product-ID overlap**: a product listed in both `NOCTRA_SUBSCRIPTION_PRODUCT_IDS` and `NOCTRA_LIFETIME_PRODUCT_IDS` aborts startup instead of silently resolving as a subscription.
- **Abuse/cost hardening**: the verify endpoint is rate-limited per IP (30 requests/minute, 429 on excess — an abuse barrier, not an authorization mechanism; real security remains Play token verification), and `purchaseToken` lengths outside 10–4096 chars are rejected before any Google call. The rate-limit partition key uses the real client IP from `X-Forwarded-For` (Cloud Run's `RemoteIpAddress` belongs to the platform proxy — using it would have collapsed all users into a single global 30 req/min limit). Play API errors (401/403/429/500/503) are covered by new client tests and still propagate as 502 — the client keeps its last verified entitlement (never drops early).
- **Lifetime acknowledge retries transient failures once**: `AcknowledgeIfNeeded` now attempts twice with a 1.5 s pause on transient responses (`SERVICE_UNAVAILABLE`/`NETWORK_ERROR`/`BILLING_UNAVAILABLE`/`ERROR`) instead of a single fire-and-forget attempt — a missed acknowledgement would otherwise risk Play's 3-day auto-refund if the user does not reopen the app.
- **Deploy now uses a project-local Dockerfile as the build context**: `gcloud run deploy` had no `--dockerfile` argument, so the scripts switched to `--source Noctra.Billing.Api` (the Dockerfile inside that folder treats it as its own build context). `artifactregistry.googleapis.com` is enabled explicitly (source deploys use Cloud Build + Artifact Registry). This unblocks clean-machine deploys that previously failed with `unrecognized arguments: --dockerfile`.

### Fixed

- **EPG refresh no longer progressively stalls or loses its Settings status**: large XMLTV imports clear EF tracking after every committed batch and compare overlap candidates only within the same channel, preventing later SQLite saves and dedupe passes from growing with the entire import. The initial large channel snapshot/filter now runs outside the UI context. Leaving Settings and returning during a refresh rehydrates the current EPG percentage/message, continues observing it, skips the competing EPG statistics scan, and refreshes the final statistics when the background operation completes. The refresh action stays disabled for the entire operation, including after leaving and returning to Settings, then re-enables automatically on completion.
- **EPG channels no longer inherit another broadcaster's guide**: XMLTV mapping now resolves each channel to one logical target set instead of unioning every display-name and `tvg-id` candidate. Exact `tvg-id` wins, conflicting display names are rejected, fuzzy matching requires high confidence plus a clear runner-up margin, and TRT/TGRT-style broadcaster collisions no longer pass. Country identity now prioritizes `Channel.Country`/`tvg-country` and explicit name/source markers; broad patterns such as `Haber`, `ATV`, `TLC`, and `DMAX` are not used as hard EPG identity, and unknown countries remain neutral instead of defaulting to the United States. The optional country classifier no longer uses raw substring hits: generic/global brands are excluded, remaining patterns require token boundaries, and only one most-specific country may win. Channel normalization preserves brand-capable `Plus`, `Extra`, `Max`, and `Sat` tokens, preventing HBO/HBO Max, S Sports/S Sports Plus, and SAT.1 collisions while still removing quality/codec/delivery noise. Genuine HD/FHD/backup streams sharing the same exact identity still receive the same guide. Programme titles and descriptions now honor the selected application language (`tr-TR`/`tr` and common XMLTV three-letter aliases included), then fall back to untagged or first available text; adjacent multilingual elements are no longer skipped by the streaming XML reader, so XML order cannot randomly choose a foreign title.
- **Mobile EPG short-program overlap**: Timeline blocks now keep their real time-derived visual width while exposing a separate minimum touch target. Short news, advertising, and sports segments no longer paint over the next program; pointer selection resolves against the actual timeline interval.
- **Mobile download center remains responsive with large season queues**: Whole-season queue creation now runs outside the UI thread, active/queued/failed lists use virtualized panels, progress and status changes update existing rows instead of resetting entire collections, refresh events are coalesced while Downloads is visible, and pause/resume/cancel operations no longer wait on network or SQLite work on the UI thread. Active-worker shutdown is bounded and transient SQLite busy errors are retried.
- **Desktop download center now virtualizes large queues**: Active, queued, and failed download sections use bounded `ListBox` controls backed by `VirtualizingStackPanel`, while preserving the existing desktop cards and commands. Transient row selection is cleared immediately and nested scrolling chains back to the page, preventing large season queues from constructing every desktop card at once.
- **User-facing error messages are now free of technical detail**: a code review sweep (DNS/HTTP/SSL/cache-clear, download, playlist preview and import, Stalker portal, player) removed every remaining leak of raw exception text, HTTP status codes, hostnames, and internal jargon (`endpoint`, `handshake`, `parse`, `HTTP 404`, `(Kod: X)` suffixes, byte counters, database/orphan-file wording). `AndroidDialogService.ShowErrorAsync` no longer appends `ex.Message` to dialogs, `UserFriendlyErrorMessage` no longer passes through `InvalidOperationException.Message` or interpolates `baseException.Message` into its unknown-error fallback (unknown failures now show a fixed localized message and are logged instead), and the Android player's `ErrorOccurred` events emit localized messages with the raw detail written to the diagnostic log. The SSL message no longer recommends downgrading `https://` to `http://` (it now advises checking the server certificate), DNS/socket messages no longer expose `getaddrinfo`/`EAI_*`, and the cache-clear confirmation no longer advertises database compaction. Translations updated in all 5 languages; a new `Error.Http.ServerUnreachable` / `Error.Generic.Unknown` key pair replaced the code-suffixed variants.
- **Deploy scripts survive multi-product IDs**: `deploy-billing.sh` / `deploy-billing.ps1` (and the manual deploy example in `docs/play-billing-verification.md`) now pass each environment variable as its own `--set-env-vars` flag instead of a single comma-joined string. `gcloud` splits `--set-env-vars` on commas, so a comma-separated value such as `NOCTRA_SUBSCRIPTION_PRODUCT_IDS=noctra_premium_monthly,noctra_premium_yearly` would have been torn into bogus key/value pairs and failed the deploy with `Bad syntax for dict arg` — multi-product configurations now deploy correctly.
- **Play subscription expiry is now verified by a backend, not estimated on-device**: The client no longer computes subscription end dates (`purchaseTime + billing period` and the `max(now + period)` over-grant were removed). Purchase tokens are sent to a verification backend (`Noctra.Billing.Api`, ASP.NET Core Minimal API — stateless, no database) that calls the Google Play Developer API (`purchases.subscriptionsv2.get` → real `lineItems.expiryTime`, and `purchases.products.get` for the one-time package), validates package/product against its own server-side config, and returns the normalized entitlement. When the verification service is unreachable, the last verified entitlement cached in settings is used (fail-safe: entitlements are never dropped early); a Play query failure no longer masquerades as "no purchases". Play access uses ADC (Cloud Run service identity); credentials never reach the client/APK. Setup guide: `docs/play-billing-verification.md`.
- **Temporary Play query failures can no longer downgrade a paid user**: `GetEntitlementAsync` previously marked the result as verified only when at least one purchase token had been successfully verified (`IsVerified = verifiedAny`). A successful Play query with an empty purchase list (a free user, or a canceled/refunded purchase no longer returned) was therefore treated like a verification failure and fell back to the cached entitlement. Now the outcome is authoritative when the query itself succeeds: no purchases means no entitlement (stale cached premium is cleared), and `IsVerified` is only false when an existing token could not be verified against the backend (network/server error) — in that case the last verified entitlement is preserved and never dropped early.
- **Child profile deletion is now atomic**: The child-profile removal migration (`DeleteChildProfilesAsync`) and the expired-profile purge (`PurgeExpiredProfilesAsync`) now run all database operations — EPG, series, import-job, playlist, profile and provider-account rows — inside a single explicit transaction with commit/rollback. Previously each `ExecuteDeleteAsync` committed on its own, so a mid-way failure could leave a half state (EPG/series/import jobs deleted while the profile still stood). File-system download cleanup stays outside the transaction (SQLite write locks) and runs first: on failure the profile is preserved and the migration retries on the next launch. The orphan-provider-account check is now computed up front so accounts shared by two deleted profiles are cleaned instead of surviving as orphans.
- **Promo failures no longer leak technical details**: Unexpected exceptions during promo redemption are logged and surfaced as a localized generic message in both mobile and desktop settings instead of `exception.Message`.
- **Mobile app failing to build/start since 32a1758**: two startup-breaking issues removed. (1) The promo-code `TextBox` used `IsTextPredictionEnabled="False"`, a property that does not exist on `TextBox` in the project's Avalonia 12.1.0 — the XAML compiler rejected it (`AVLN2000`), so the mobile project could not compile at all (incremental builds skipping XAML compilation had been masking this). The attribute was removed (no valid auto-correct toggle exists in this Avalonia version). (2) The global `MaterialIcon.Rotating` animation style added to `Noctra.Mobile/App.axaml` — loaded before the main screen at startup — animated `RotateTransform.Angle` on icons that have no `RenderTransform`, a runtime XAML risk. The style is removed and the promo loading icon now uses the library's built-in `Animation="Spin"` (verified valid by the XAML compiler in Material.Icons.Avalonia 3.0.2). The same risky `Rotating` pattern in the desktop `GlobalSettingsWindow` promo spinner was migrated to `Animation="Spin"` as well; the desktop `SettingsWindow` keeps its correct explicit-`RotateTransform` pattern.

Success messages were made calm and warm ("Kanallarınız hazır!", "Program rehberi hazır!") without exclamation overload. Progress formats now render as `{1} ({2}%)` (TR: `{1} (%{2})`, FR: `{1} ({2} %)`); `Settings.Status.Refresh.Label` and `Settings.Status.Stats.ErrorFormat` reduced to `{0}` (format arguments are unchanged in code, so `string.Format` simply ignores the extras). Technical labels remain only where a value is expected input (`Settings.Epg.UrlPlaceholder`, download-folder hints). Keys keep their `Epg` names (implementation detail); translations were updated in all 5 languages.

The sheet no longer closes when the Play billing window merely *opens* or when the user cancels — `LaunchBillingFlow` success/cancel keep the sheet open, and it closes only when the actual purchase completes (`OnPurchasesUpdated` → entitlement refresh → `SubscriptionChanged` → Premium). Pending payments show the localized "payment pending" message in the sheet; errors keep it open with a retry path; the URI fallback (store-unsupported hosts) still closes on launch.
- **No cross-plan fallback in the mobile upsell flow**: tapping the Lifetime card could previously open the *monthly* payment screen when the lifetime product was missing from Play — `PurchaseAsync` fell back to the general `StartPurchaseFlowAsync` (which prefers the subscription) whenever the requested product was null. The fallback now runs only when the store is unsupported (URI flow); a missing requested plan shows a dedicated localized "this plan is currently unavailable" message (`Upsell.Plan.UnavailableKind`, added in all 5 languages) and never opens another plan's payment screen.
- **Pending purchase UX (mobile)**: a purchase waiting for Play approval (e.g. carrier billing) no longer silently disappears after the upsell sheet closes. `StoreEntitlement` now carries a `HasPendingPurchase` flag set by the Android store service when any queried purchase is `PENDING`; `LicenseService` exposes it (`HasPendingStorePurchase`) and notifies on change, and the mobile settings screen shows a localized "payment pending" banner above the upgrade button until the payment resolves. - **`.env` repo-root detection uses the real solution name**: the debug `.env` loader stopped its upward walk only on `Noctra.sln`, which does not exist (the repository solution is `NoctraPlayer.sln`), so it could climb past the repo root and pick up a stray `.env` from a higher directory; it now anchors on `NoctraPlayer.sln`.

The mobile upsell sheet now hides the plan cards entirely for lifetime owners (the monthly plan is never offered), asks for explicit confirmation when a user with an active monthly subscription taps Lifetime (the subscription will keep renewing), and after the lifetime purchase completes while the monthly subscription is still active, keeps the sheet open with a localized reminder and a "Manage Subscription" action that opens Google Play's subscription management page. - **Duplicate provider restriction**: The check that prevented adding the same M3U/Xtream/Stalker provider in multiple profiles was removed. Users can now use the same provider account across different profiles.

### Fixed

- **VLC airspace overlay focus recovery**: Video controls no longer disappear permanently after switching to another application and returning to Noctra. The detached overlay window restores its native z-order above the VLC HWND without taking activation.
- **Overlay controls after auto-hide**: Hidden playback controls can be shown again by pointer movement because the transparent overlay and mouse-capture surfaces remain native hit-testable.
- **PiP overlay lifecycle**: PiP controls remain recoverable after auto-hide, and leaving PiP restores normal player controls instead of leaving the overlay behind the video surface.
- **Owner-relative overlay behavior**: The video overlay follows the main window's visibility, minimized state, and PiP topmost state without foreground-process polling or forcing controls above unrelated applications.
- **Watermark text clipping**: Random watermark movement now transforms the complete watermark control instead of its inner border, preventing the first letter of "Noctra - Free" from being clipped at some positions.
- **Series detail empty-provider state**: Series with no provider seasons/episodes no longer keep stale Play/Continue episode actions, and the detail page now shows a no-episodes message instead of an endless loading spinner.
- **Series detail loading scope**: Episode loading UI is now tied to selected-series metadata loading, not global channel-list background loading.
- **Settings ComboBox overflow**: Refresh frequency, EPG timezone, and content filter ComboBoxes no longer clip selected text or resize awkwardly when labels are long.
- **Settings selection animations**: Selecting settings ComboBox values no longer incorrectly triggers unrelated tab/slide transition behavior.
- **Resume dialog time display**: The "Where you left off" time now restores itself while the resume dialog is visible, preventing blank position text when late playback state resets occur.
- **Mute state synchronization**: Restored mute persistence so reopening the app keeps UI mute state and actual player audio aligned; service volume events no longer unmute playback implicitly.
- **Profile settings leakage**: Promo code state and Microsoft Store review prompt state are no longer written into per-profile settings files.
- **Global settings leakage**: Profile-only values such as EPG refresh, custom EPG URLs, watch-history settings, and hidden group lists are no longer written into the global settings file.
- **Tampered promo grant handling**: Invalid or manually edited promo grant values no longer crash settings/license loading and simply leave the app in Free mode.
- **Stalker VOD poster fallback**: Stalker VOD list parsing now ignores blank poster fields such as `pic=""` and falls through to populated fields like `screenshot_uri`, fixing gray VOD cards when the provider already returns poster URLs.
- **Stalker Series episode artwork fallback**: Stalker Series and episode parsing now skips blank image fields and falls back through `screenshot_uri`, `icon`, `cover`, `movie_image`, `screenshot_url`, and the parent Series cover.
- **Xtream Series and episode artwork fallback**: Xtream Series detail, Series list, season, and episode parsing now use the same first-nonblank image fallback behavior across `cover`, `stream_icon`, `cover_big`, `movie_image`, `poster`, `image`, and `screenshot_uri`.
- **M3U account URL layout**: Long M3U playlist links in Settings now wrap inside the account card instead of overflowing or rendering as a form input.
- **Review prompt timing**: The review prompt is global across profiles, waits for an eligible main-menu surface, delays during the active session, never appears over video playback/overlay/PiP/details/global loading or other dialogs, and snoozes for 3 days when the user chooses Later.
- **Review dialog ownership**: The review prompt is no longer topmost, so it stays owned by the main app instead of floating independently over fullscreen video, while existing app dialogs keep their established topmost behavior.
- **Stalker progressive resume stalls**: Stalker category loading now times out stuck categories, clears their dummy card, and continues with the remaining queue instead of leaving progress frozen.
- **Progressive load UI stalls**: Cached Xtream/Stalker resume now runs off the UI thread, and Series/Home refresh work is deferred until channel loading completes.
- **Progress status overwrite**: Background aggregation no longer replaces active provider progress with "Channel List Ready" while the playlist is still loading.
- **Stalker resume matching**: Pending dummy categories now expose both group names and provider category IDs, so resume works even when localized or special-character group names shift.
- **Dummy Series aggregate leak**: Progressive `stalker-dummy://` and `xtream-dummy://` rows no longer create stale Series cards such as "Content loading".
- **Duplicated progress status text**: Channel-loading status now renders one primary progress message instead of repeating the same text twice in the status bar.
- **View-switch content bleed**: Live, Movies, and Series navigation now clears the target content surface before the new view renders, preventing old cards from flashing under the new page title.
- **Profile switch background loading leak**: Large Xtream/Stalker progressive loads are now cancelled and prevented from updating progress/status after profile switch or app close.
- **Connection health accuracy**: Connection badges no longer default to "good"; Add Profile and save validation now use the same provider auth/content rules, and M3U health checks are profile-scoped with GET fallback.
- **Category image stall**: Categories that reached the end of visible scroll without creating enough scrollable height can now request additional pages.
- **Search cards without posters**: Search and similar-result sections now queue visible VOD/series image fallback when provider posters are missing.
- **Provider Series poster latency**: Xtream/Stalker Series list cards no longer perform per-card provider detail artwork requests; only posters present in the provider list response are rendered immediately, keeping large lists responsive.
