# Mobile Card Action Sheet Design

## Scope

Replace every native long-press `MenuFlyout` owned by the shared mobile media
cards with one application-styled action sheet.

The shared cards cover:

- Live, Movies, and Series primary grids;
- Home Continue Watching;
- Search and similar results;
- Favorites;
- My List;
- History.

Category rows, series episode rows, download rows, and player controls are out
of scope because they do not currently expose the card context menu being
replaced.

The sheet opens only through a long press. No persistent overflow button is
added to any card.

## Selected Architecture

`MainView` hosts one `MobileCardActionsSheet` in its root overlay grid at
`ZIndex="47500"`. The sheet sits above the shell, bottom navigation, and
category overlay, but below playback and modal flows that must retain higher
priority, such as legal consent and profile selection.

Shared card controls raise one routed card-action request containing:

- the media object currently bound to the recycled card;
- the card presentation mode;
- the media kind;
- only the action capabilities required to build the sheet.

The cards do not own a sheet and do not retain a reference to an item after the
request. `MainView` resolves the current `MainViewModel`, builds the available
actions, and opens the single host.

This avoids duplicating overlays in every screen and keeps virtualization safe:
the selected media is captured when the long press completes, before the card
can be recycled for another row.

## Long-Press Gesture

`MobilePressableCard` owns the gesture arbitration so all four shared card
controls behave identically.

- A primary touch or left mouse press starts the pressed visual and a
  long-press timer of approximately 500 milliseconds.
- Moving at least 12 device-independent pixels cancels the timer and pressed
  state so vertical scrolling remains responsive.
- Releasing, exiting, losing capture, detaching, or starting on a nested button
  cancels the timer.
- When the timer completes, the card raises a long-press event and suppresses
  the tap generated by that same pointer sequence.
- A normal short tap continues to open or play the card.
- The Live favorite button remains independent and never opens the sheet.
- Only one pointer sequence and one sheet request may be active at a time.

Native `ContextFlyout` and `MenuFlyout` resources are removed from all media
cards, so Android never renders the platform context menu.

## Sheet Layout and Interaction

The sheet follows the existing mobile selection-sheet visual language while
remaining compact:

- full-window dimmed scrim;
- bottom-aligned surface with rounded top corners;
- centered maximum width suitable for tablet layouts;
- drag handle;
- media title with ellipsis;
- close button;
- vertically stacked, icon-and-label action rows;
- destructive remove actions use the error color and appear last.

The sheet closes through:

- selecting an action;
- tapping the scrim;
- tapping the close button;
- dragging the handle down past the existing dismissal threshold;
- Android back or Escape.

The sheet closes before executing the selected command. Repeated long presses
replace the pending request rather than stacking multiple sheets. The sheet
clears all references and callbacks when dismissed.

Every action row receives an accessible name matching its localized label.
Focus moves into the sheet when it opens and does not activate the underlying
card.

## Action Rules

Actions are generated from the card's presentation mode instead of relying on
menu-item visibility bindings.

### Standard grids and Search

For VOD and Series:

- Add to My List.
- Toggle favorite when the media type supports favorites.

For Live:

- Toggle favorite.

### Continue Watching

- Add to My List.
- Toggle favorite when supported.

The existing Continue Watching resume flow remains a short-tap behavior and is
not duplicated inside the action sheet.

### My List

- VOD and Series: Toggle favorite when supported, then Remove from My List.
- Live: Toggle favorite, then Remove from My List.

### Favorites

- VOD and Series: Add to My List, then Remove from Favorites.
- Live: Remove from Favorites.

The old VOD and Series flyouts could show both the generic favorite toggle and
the explicit remove action in this mode. The new sheet removes that duplicate
and exposes only the unambiguous removal action.

### History

- VOD and Series: Add to My List, toggle favorite when supported, then Remove
  from History as the final destructive action.
- Live: Remove from History.

Commands remain the existing `MainViewModel` commands. This change replaces
only presentation and gesture routing; persistence and backend behavior stay
unchanged. In particular, the sheet does not add actions to Live modes where
the native flyout did not already provide them.

## Back Navigation and Overlay Priority

`MainView.TryHandleBack` closes `MobileCardActionsSheet` before category sheets,
screen-local selection sheets, navigation, or app exit.

Opening profile selection, starting playback, changing the top-level
destination, or detaching `MainView` closes the action sheet to prevent an
action from surviving into another screen.

The action sheet does not hide application chrome; the scrim covers it and
blocks pointer input while the sheet is visible.

## Failure and Race Handling

- A recycled card cannot mutate the requested target because the target is
  captured when the long press completes.
- Commands are executed only when `CanExecute` still returns true at selection
  time.
- If the active profile or view model is unavailable, the request is ignored
  and no empty sheet opens.
- If no valid actions exist, the sheet does not open.
- Closing or replacing the sheet invalidates the previous callbacks.
- Gesture cancellation never executes either the card tap or a sheet action.

## Testing

Automated tests cover:

- no `MenuFlyout` or card `ContextFlyout` remains;
- the shared pressable card starts, cancels, and completes long press correctly;
- movement, release, detach, nested buttons, and pointer cancellation stop the
  long press;
- a completed long press suppresses the following short-tap action;
- Standard, Continue Watching, My List, Favorites, and History modes generate
  the correct non-duplicated actions;
- destructive actions are ordered last;
- action execution rechecks `CanExecute`;
- `MainView` hosts one root action sheet and handles Back before navigation;
- dismissal clears the selected media and callbacks;
- localization and accessibility labels are present.

Post-change verification includes the relevant .NET tests, Android build, and
physical-device checks on each participating screen. Device checks cover short
tap, long press, scroll cancellation, scrim/back/swipe dismissal, repeated
long presses, recycled cards after scrolling, and action correctness.
